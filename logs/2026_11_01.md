## Longhorn GPU monitoring

- Audited the previous GPU-monitoring attempt. It had started an unmanaged Windows exporter from the WSL repository path, created broad Private/Public TCP and UDP firewall rules, changed Prometheus with a public machine-specific address, and published a dashboard that still reported an error.
- Removed the unmanaged process, its two firewall rules, listener, binary/archive, broken dashboard, and abandoned repository changes. Restored the clean Prometheus configuration and confirmed the existing monitoring targets and inference service remained healthy.
- Tested NVIDIA telemetry inside WSL. DCGM was not selected because this WSL environment exposes `/dev/dxg`, lacks Linux `/dev/nvidia*` devices, and has limited NVML support. Verified `nvidia_gpu_exporter` 1.16.0 against WSL's `nvidia-smi` for utilization, GPU power, used/total VRAM, temperature, and clocks.
- Installed the checksum-pinned exporter as a WSL user systemd service on loopback port 9835 with a 15-second collection interval. Added a narrowly scoped Windows portproxy and Private/TCP firewall rule allowing only Bronco.
- Measured three 512-token Gemma inference runs before and during exporter collection. Median generation changed from 84.46 to 83.49 tokens/second, a 1.15% decrease within the observed run-to-run variation. No inference stop or model unload was required.
- Enabled the Prometheus job through an ignored local values file. The live target was healthy and all five required metric families returned current samples.
- Published `Ranch / Longhorn GPU`. The saved definition matched the repository and all 11 literal dashboard queries returned finite samples. Browser-rendered layout validation remains outstanding.
- Added versioned service/firewall configuration and documented topology, installation, validation, rollback, limitations, and the difference between the k3s nodes and Longhorn.
